01

一句话看懂

先建立直觉，再谈细节。

Fact过去十年，AI 编程工具都建立在一个心照不宣的假设上：你想改的代码，就摆在你面前。但真实世界不是这样——好用的功能藏在没源码的桌面 App 里，奇怪的行为出在编译后的依赖库里，升级翻车后唯一的线索是"编译出来的程序到底在干什么"。REA 要解决的就是这个问题：给 AI agent 一套"读懂没源码软件"的工具。

Analysis它的定位不是"又一个反编译器"，而是反编译器的总调度。Hopper、Ghidra、IDA Pro、JADX、Binwalk 这些专业工具早就存在，难的是让 agent 会用它们：知道什么时候该反编译哪个函数、沿着调用链追到哪一层停、以及最重要的——怎么不把猜测当结论。REA 的全部设计都围绕这三件事。

图 1 · REA 的三步工作流。README 原话："decompile to recover readable code and naming clues, trace execution until the feature is explained, then recreate the logic in your own stack."（反编译找回可读代码→追踪到讲清功能→在自己的栈里重写）
一句话记住它：REA = MCP server + CLI，把 Hopper / Ghidra / IDA Pro / JADX / Binwalk 等本地分析引擎包装成 AI agent 能调用的 99 个工具，外加一套"每个结论必须自带证据和未知项"的约束设计。npx rea-agents setup 一行命令接入 12 种 agent。

03

三步工作流：反编译 → 追踪 → 重构

这是 README 首页 pitch 的核心，也是 agent 使用 REA 时的实际循环。

🔧 上手：两条路 Fact

给 agent 用（MCP）：npx rea-agents setup —— 选你的 agent，检查它提议的配置修改（会备份原配置），重启 agent。然后直接用人话下指令：

"Understand how search works in the Notes app, show me the evidence, and build a similar feature for my project."

给人用（CLI）：npx -y rea-agents@latest analyze-javascript-application /path/to/app --json —— 直接分析一个 Electron App 目录或 ASAR 包，输出模块、import 关系、Electron 主进程/渲染进程边界。原生二进制分析先配 provider（Hopper/Ghidra/IDA 三选一）。rea doctor 一键体检环境。

AnalysisYouTube 评测特别提到一个细节：setup 会展示确切要改的配置文件路径、改前备份、只预选已装 REA 的 agent——这种"不乱动你环境"的谨慎，在 MCP 工具普遍被诟病乱写配置的当下，是口碑加分项。

① Decompile：把黑盒变灰盒

按目标类型选引擎：原生二进制走 Hopper/Ghidra/IDA，APK 走 JADX，固件走 Binwalk/Unblob。输出伪代码 + 汇编 + 字符串 + 符号 + 调用关系——注意，是"可读的代码线索"，不是"原始源码"。

② Trace：顺藤摸瓜

analyze_function → find_xrefs_to_name → get_call_graph → trace_feature。Agent 沿着"谁调了谁"一层层跟，直到能解释目标功能。跟不下去的地方记为 unknown，不许脑补。

③ Recreate：在你的栈里重写

Agent 用前两步的发现写实现，然后 verify_reconstruction 做编译字节比对——DX-Ball 案例里 63 个字节全对才算过关。这是"可独立验证"的硬证据，不是"我觉得像"。

Analysis这个工作流最聪明的一点：它把"逆向"变成了"可审计的科学实验"。传统逆向是专家脑子里的一团直觉；REA 强迫每一步都留下证据 ID 和未知项，最后还能用"重新编译、逐字节对比"来证伪。DX-Ball 和 TH04 两个 showcase 之所以有说服力，正因为它们用的都是这种第三方可复现的验证方式。
04

架构深读：不造反编译器，只做编排

读完 docs/architecture.mermaid 全图后提炼：REA 的架构赌注是"编排广度"，不是"单点深度"。

图 2 · REA 架构。核心洞察：它不重新实现反编译（那是 Hopper/Ghidra 干了十年的事），它实现的是"让 agent 正确使用反编译器"的编排层 + 证据约束层。仿 docs/architecture.mermaid 重绘。

💥 v4.0.0：一次"做减法"的 breaking Fact

10 月 5 日的 v4.0.0 删掉了两大子系统：Replay（进程/浏览器回放、检查点、reactive scenarios 整套移除）和 permission-policy（自带的权限审批模型、approval 字段）。替代品是无状态的 native inspection primitives + 调用方自理权限。

Analysis这是典型的架构清醒时刻：MCP host（Claude Code 之类）本来就有自己的 permission 模型，REA 再造一套审批框架是重复造轮子，还添乱。砍掉有状态的回放编排，退回无状态检查原语——把"编排"还给 agent，把"检查"留给自己。代价是调用方必须刷新 tool schema 并迁移被删字段。4.0→4.1 只隔一天，正是"先破后立"的节奏。

🧰 99 个 MCP 工具：读多写少 Fact

数自源码 src/server/register*.ts：ADB/设备 22、原生二进制 21、JS/Electron 13、Web/浏览器 10、Evidence/工作流 11、固件/EVM/JEB 等 12。动词分布 inspect_* 22、list_* 11、trace_* 7、compare_* 6——读多写少，符合"只读取证"的定位。

🚀 5 天 8 版：流量倒灌倒逼迭代 Fact

10-07 v5.0.0 → 10-11 v6.4.0，5 天连发 8 个版本（含 3 次 breaking）。v6.4.0 单版 336 commits / 163 merged PRs，致谢了一串外部贡献者。维护者 morluto 主页显示此前还有 gbrain、Orca 等 agent 项目——高频迭代是本来就有的习惯，爆火只是放大器。

06

Evidence 哲学：最值得抄走的设计

如果只从这个项目带走一样东西，带走 EvidenceLedger——不是 99 个工具，是"结论必须自带证据"的约束。

图 3 · Evidence 数据模型。每个结论 = 证据 + 置信度 + 未知项 + 边界声明。这正是取证报告里"事实 / 存疑 / 不覆盖"章节的机器可读版。

🧪 为什么这能防幻觉 Analysis

LLM 做逆向最大的风险不是"看不懂汇编"，而是太会编故事——给一段伪代码，它能讲出三种 plausible 但全错的解释。REA 的对策是三件套：

  1. Unknowns 显式建模：record_unknown → update_unknown → verify_unknown，没确认的就是没确认，agent 不能跳过这一步直接下结论；
  2. 可证伪的验证闭环：verify_reconstruction 用"重新编译、逐字节对比"这种第三方可复现的方式打脸，比"让另一个 LLM 评审"硬得多；
  3. 快照与比对：分析快照可导出，compare_functions / compare_artifacts 天然支持"两个版本的 diff 取证"（补丁分析、供应链投毒比对）。

这套东西的价值超出逆向本身——任何"让 agent 做取证、写报告"的场景都缺这一层：把"我发现了什么""证据在哪""还有什么没确认"变成一等公民，而不是藏在 markdown 散文里。

07

Showcase：三个硬核案例

官网 rea.tools/showcase 上的实战。选这三个讲，因为它们的验证方式都是"第三方可复现"的。

🎮 DX-Ball：63 个字节，全对 Fact

1996 年 Windows 游戏 DX-Ball 1.07，砖块击中音效的左右声道平衡（pan）是怎么算的？Agent 用 REA 检查 0x406400 函数，发现反编译器漏掉了 [EBP+8] 的整数输入；跟踪调用者 0x411f40 得出屏幕坐标公式 20 + 30 × tile_x；再从内存常量读出 1.5625 / 500.0 / 1.0 三个运算数。重构出的 C 函数通过 3,205 个原始 x86 行为测试，并用锁定的 VC4.0 工具链编译，复现了全部 63 个字节。整个 DX-Ball 重构已恢复 55 个 C 函数，其中 33 个字节级匹配。

Analysis这个案例的杀伤力在于：它证明了 agent 不只能"看懂"，还能"精确重建"——而验证标准（字节级一致）是任何人都可独立复跑的。这正是 REA 自己宣扬的 Evidence 哲学的自我证明。

📋 Notion：一条复制链路的跨进程追踪 Fact

Notion Desktop 7.6.1 的"复制"走了多远？从渲染进程的 window.__electronApi.clipboard.write 出发，经 preload 包装 → ipcRenderer.invoke → 主进程 ipcMain.handle → 发送者校验 isNotionWebContents(event.sender) → Electron 原生剪贴板。同时还原了富文本机制：HTML 里藏 <!-- notionvc: <copy-id> -->，另以 text/_notion-blocks-v3-production MIME 存结构化 block 数据。顺带还追出一条"离线 SQLite 连接"——主进程经 MessageChannel 把端口分给渲染进程和 SQLite 工具进程。

Analysis这个案例展示的是跨进程追踪能力：preload → IPC → main → native，一层层跟下去。对取证来说，这正是"一个功能到底碰了哪些进程、过了哪些校验"的标准问法。

👾 TH04：16 位 DOS 弹幕的瞄准算法 Fact

东方 Project TH04（PC-98，16 位 DOS）的 Boss 弹幕：16 发子弹的圆环，一周记为 256 角度单位，每发间隔 16 单位（22.5°）；用 iatan2 算出玩家方向后整体旋转叠加。REA 检查 MAIN.EXE 的 DOS MZ 镜像，定位 0x2cfc8 的 SHL AX,8 / IDIV 定点除法与瞄准分支，还原出 aimed_ring_angle()。用锁定的 Turbo C++ 4.0J 编译，2,139 字节与原可执行文件对应段完全匹配，且两次独立构建字节一致。

Analysis连 16 位实模式的老古董都能啃，说明它的引擎编排确实做到了"足够通用"。两次独立构建字节一致这个细节，是可复现性的教科书写法。

为什么爆火：数据、传播链与时机

10 月 8 日 #8，10 月 9 日 #1，单日 +15,335 star。拆一下这波流量是怎么来的。

图 4 · Star 增长曲线。数据来源：GitHub API（10-11 实测 82,642）+ 第三方 trending 统计（各家口径/时点不同，量级一致）。注意 4–9 月的平缓期：那是攒底子的 4 个月。

📣 传播链 Fact

  • 媒体：startupfortune 10-09 首发深度报道、Medium levelup 8 分钟长文、runtimewire、ai-tldr、YouTube 评测视频；
  • KOL：Matthew Berman 10-08 在 X 推广，称其时刻为 "Software is done"，类比 Napster 早期；
  • Meme："soon all software will be open de facto"（Replit 创始人 Amjad Masad）待核实——公开搜索未找到原帖，暂列传播背景，不当事实引用。

🎯 为什么是它 Analysis

  1. 演示力：DX-Ball 63 字节全对，是 RE 圈看得懂的硬核 demo，比 benchmark 更有说服力；
  2. 接入成本：一行 npx 进 12 种 agent，吃到了 agent 爆发的红利；
  3. 叙事：Napster 类比精准——Napster 没让音乐"免费"，它让分发摩擦归零；REA 让理解闭源软件的摩擦归零；
  4. 时机：撞上"AI × 逆向/安全"舆论风口（见 §9）；
  5. 底子：19 语言文档、MIT 协议、showcase——流量来了接得住。
Hypothesis还有一层可能被低估的原因：恐惧驱动的好奇。Artex 韩国银行事件（见 §9）让"AI 能看懂二进制"从极客话题变成公共安全议题，REA 恰好是这个议题下唯一一个"普通人也能 npx 装上"的实物。很多人 star 它，不全是因为要用，而是想亲眼看看"到底能做到什么程度"。
09

双用途与红线：Artex 不是 REA

爆火的同时，它也被放进了"AI 黑客工具"的叙事里。这一节专门澄清事实、划清红线。

事实澄清造成韩国七家银行入侵的 AI agent 是 Artex，不是 REA。WSJ 报道：攻击者用 Artex（中国安全工程师李溥骅的开源 AI agent）侵入韩国至少 7 家金融机构，约 68,000 人信息泄露，韩国警方已立案；Artex 作者随后宣布停更转闭源。startupfortune 写 REA 时的原话是 "a different AI agent"——两个项目只是时间相近被放进同一叙事，混为一谈是误读。
图 5 · 双用途光谱。工具本身是中性的，栏杆是姿态。注意：反编译产物仍是他人 IP，"反编译"不等于"洗白版权"——README 把合规责任转给了用户，执行靠自觉。

🪙 警惕同名诈骗币 Fact

README Disclaimer 第二段原文大意：我们没有发行、也没有背书任何加密货币或 token，冒用 REA 名字的 token 与本项目无关。这是爆火项目的标配遭遇——流量起来后第一时间就会有人发诈骗币，项目方专门加了这条声明。看到 REA token，一律按诈骗处理。

⚖️ 法律边界一句话 Analysis

逆向工程的合法性因司法辖区而异（安全研究、互操作性在多数地区有例外，但绕过技术保护措施、违反 EULA 另算）。REA 的自我约束——证据+caveat、本地运行、不宣称恢复源码——是它与"盗版工具"划清界限的话术，也是取证场景下可用的信任基础。但话术不是护身符：拿它分析无权分析的目标，责任在你，不在工具。

10

对取证工作的价值：能拿走什么

站在"取证分析 AI agent 产品"的视角（本档案馆的老本行），给 REA 做一次能力审计。

✅ 拿来就能用的四样 Analysis

  1. 本地取证工作台：样本不上云——恶意软件、企业闭源软件取证的硬性要求，这是相对任何云端 RE API 的结构性优势；
  2. Evidence bundle 即证据包：可导出/导入/比对，天然对应取证的"证据包 + 监管链"；compare_functions 可直接做"两版本 diff 取证"（补丁分析、供应链投毒比对）；
  3. Unknowns 账本即反幻觉机制：强制要求"写进报告的结论必须有 evidence_id 或 unknown_id"，否则打回——取证报告最怕 LLM 把推测写成事实；
  4. 崩溃与行为取证：crash 记录分析、进程行为捕获与比对、静态↔运行时关联，覆盖了"程序到底干了什么"的另一半。

🚫 指望不上的四样 Fact Analysis

  1. 作者明确声明：不恢复原始源码、不整体克隆应用——想"一键抄个 App"的人会失望，这是定位不是 bug；
  2. 动态能力弱：v4.0 砍掉了 replay 体系，Frida/x64dbg/GDB 动态调试还在 issue 阶段（#1267、#968）；
  3. 混淆/加壳是短板：roadmap 自己把"混淆 managed-code 比对"列为待改进；
  4. Windows 链路补课中：#287 等长 thread 讨论 Windows native 权限，大目标性能有回归（#1387）。
Analysis给 openmuse / Cassia 的建议：值得借鉴的不是那 99 个工具，而是 EvidenceLedger + Unknown 所有权这套"结论必须自带证据和 caveat"的数据模型——这正是 sandbox 取证 agent 最缺的一层。如果要集成，集成它的 MCP 工具层 + Evidence 模型；不要直接信任其重构输出，关键结论走人工复核。定位应该是"第一遍自动化初筛 + 证据整理"，最终定性仍归人 + 专用工具（IDA/Ghidra 原生）。

🥊 竞品格局一句话 Fact

同类里 bethington/ghidra-mcp（~4,979★，200+ tools）是 Ghidra 单引擎深度派，REA 是多引擎广度派。REA 的赌注是："agent 需要的不是更好的反编译器，而是统一的取证工作台"。风险也在这：多引擎 = 每个都不够深，硬核 RE 仍会回到专用工具。真正的壁垒是工作流沉淀——Evidence/unknowns/snapshot 这套"让 agent 不 hallucinate 的约束设计"，抄工具列表容易，抄这个难。

11

短板与风险：爆火之后的问题

82k star 不等于 82k 个深度用户。把问题摆出来，再决定要不要上生产。

1️⃣ 围观型爆火，深度用户还少

149 个 open issue 里 reaction 普遍是个位数——star 暴涨但动手的人少。好消息是 v6.4.0 有 163 个 merged PRs，核心贡献圈已转起来。

2️⃣ 迭代太快，API 不稳

5 天 8 版、3 次 breaking。v6.0 强制绝对路径、v6.4 Evidence 语义变更（旧 bundle 需重跑）。跟得紧才吃得到红利，跟不上就是迁移成本。

3️⃣ 依赖商业工具链

深度原生分析要 Hopper（商业）/ IDA（商业）或 Ghidra（免费但重）。setup 可代装 Hopper（需审批），但 license 成本和 Ghidra 冷启动超时（#1048）是真实门槛。

4️⃣ MCP 生态碎片化

#1416 揭示：Hex-Rays 官方 IDA MCP 与 REA 用的社区版工具面完全不重叠——连同一家的两套实现都不兼容。REA 的"多 provider 适配层"每多一个后端就多一份映射债。

5️⃣ 爆火暴露的工程债

#1065（💬40，全场最热）：大 JS 分析会断开 MCP 客户端连接、取消不能及时停、Windows 首次 Ghidra 分析超客户端默认超时。用户从几百变几万，schema 体积和冷启动问题立刻现形。

6️⃣ 取证视角的最大风险

Agent 会自信地把"证据支持的推测"写成结论。必须把 unknowns / limitations 当强制阅读项，而不是可选项——否则 Evidence 模型只是更精致的幻觉包装纸。
