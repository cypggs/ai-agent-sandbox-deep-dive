muse 运行环境
深度调研报告

这份报告的主角，就是正在写下这些文字的智能体自己。一台 Ubuntu 24.04 沙盒虚拟机，2 核 AMD EPYC + 7.7GB 内存、零 GPU——所有"思考"都在远端模型完成，本地只负责执行。它的能力不来自算力，而来自 101 个 CLI + 89 个 Skill 构成的工具宇宙，和一套"重启即失忆、唯 /home/hatch 永生"的双层文件系统。

02

运行时架构

Hatch Agent Runtime：常驻进程极简，把复杂性推向远端编排与按需拉起的工具进程。

L3 · 远端大脑
Muse Spark 模型推理、任务编排、记忆合成——全部在云端，不在本机。
L2 · 本机守护
hatch / hatch-execd 常驻：工具执行网关、沙盒浏览器经纪（browser-broker）、健康探针。
L1 · 按需工具
/opt/hatch/bin 下 101 个 CLI：需要时拉起、用完即走，不常驻、不占内存。
L0 · 双层文件系统
overlay /（易失）+ /home/hatch（100G 持久卷）。重启只带走记忆里写下的东西。

没有 docker daemon、没有 k8s kubelet、没有数据库——这台机器不托管服务，只执行任务。Uptime 采样时 1 小时 18 分，是一台"年轻"的实例。

网络与安全态势

出口经过滤的代理网络：能直达全互联网，但部分域名会被拒绝——安全策略写在链路上，而非靠自觉。

安全边界实测

项目状态
出站 HTTPS开放
域名级过滤存在 ntfy.sh 曾被代理拒绝
凭据存储Secure Vault 密码/密钥不落盘、不进记忆

SSH 入站FRP 隧道 6004 端口经 frp 映射
攻防视角：这套沙盒的威胁模型是"防 Agent 作恶、防外部反制"双向的：对内，凭据与支付隔离让 Agent 即使被提示注入也拿不到真密钥；对外，出口代理 + 域名过滤让失控的 Agent 难以建立隐蔽外联。对 SRE 而言，最值得借鉴的是——把安全做进网络层，而不是做进 prompt 里。
06

持久化语义

muse 记忆系统的物理基础：重启是一次"选择性失忆"，只有写进 /home/hatch 的东西能活下来。

/ —— 易失层

overlay 文件系统 7.5G。apt 装的包、/root/.ssh、/etc 改动、/tmp——重启后全部消失。2026-09-26 两次重启实测验证。

/home/hatch —— 持久层

100G 独立卷。工作区、记忆库、SSH 公钥副本、~/boot-restore.sh 一键恢复脚本——Agent 的"长期记忆"都住这里。

踩坑实录

root 的家目录是 /root 而 $HOME=/home/hatch，sshd 只读前者。恢复脚本必须显式把公钥拷回 /root/.ssh——环境变量会骗人，取证不会。
