系统架构与虚拟化

03

硬件资源配置

🧮 CPU — Intel Xeon @ 2.50GHz

3 物理核 × 2 超线程 = 6 vCPU，单 Socket 单 NUMA 节点。Family 6 Model 85（Skylake-SP 世代虚拟型号），指令集亮点：AVX-512 全家桶（f/dq/cd/bw/vl + VNNI）、AES-NI、FMA、BMI2。L3 缓存 35.8 MiB。适合中等强度并行计算与 ML 推理前处理。

🧠 内存 — 7.8 GiB + 2 GiB Swap

无 cgroup 限额，OOM 防护依赖 earlyoom（可用内存 <10% SIGTERM、<5% SIGKILL），且配置了保护名单豁免 supervisord、sandbox-runtime、Xorg、x11vnc、statesync、manus-* 等关键进程。swappiness=0，swap 仅吸收匿名页尖峰。

💾 存储 — 51 GB virtio 根盘

/dev/vda → ext4 (rw,noatime)，已用 12G / 可用 40G。/dev/shm 为 2G tmpfs；Chromium 以 --disable-dev-shm-usage 规避 shm 不足。另有 fusectl 支持 FUSE（ws-mount 使用）。

🎮 GPU — 无物理 GPU

图形渲染走 SwiftShader（--use-angle=swiftshader-webgl）CPU 软渲 WebGL，Xorg 虚拟屏 1280×1029@24bit。Chromium 还加载了 OnDeviceModelService（端侧模型沙箱进程）。

04

启动链路剖析

从 VM 上电到代理就绪的完整引导链。核心文件 /e2b-startup.sh（3 行转发）与 /startup.sh（约 400 行，含完善的守护与自愈逻辑）。

systemd (PID 1) → envd.service

E2B 守护进程，OOMScoreAdjust=-1000（最后被杀），GOMEMLIMIT=64MiB，每 10s 回收冷页缓存（保留 1024MiB）。执行 /e2b-startup.sh。

/e2b-startup.sh → sudo -u ubuntu /startup.sh

切换到非特权用户 ubuntu 执行主引导脚本。

/startup.sh — 环境准备阶段

加载 ~/.env（平台注入）与 ~/.user_env（用户连接器凭据，如 GH_TOKEN、GOOGLE_DRIVE_TOKEN）；向 .bashrc/.zshrc 注入 env 自动加载、PYTHONIOENCODING=utf-8、PIP_BREAK_SYSTEM_PACKAGES=1；用 uv 包装 pip/pip3（install 走 uv pip --system）；创建 /var/lib/manus 持久状态目录；启动 dbus（固定 well-known session bus 地址）。

拓扑环境冻结（runtime-topology-env.sh）

capture/restore_supervisor_runtime_env：在加载用户密钥之前快照平台可信拓扑变量，之后恢复——防止用户级 .user_env 覆盖运行时关键配置（fail-closed 设计）。

supervisord 拉起托管进程组

先强制清理残留 sandbox-runtime / runtime-upgrade（注释中记录了 commit 9821822a8 的 SIGKILL 竞态不变量），再启动 supervisord。等待 localhost:8330/healthz 与 8340/health 就绪（各 30 次重试）。

monitor_and_restart 守护循环（每 10s）

从 IMDS 获取 instanceID 写入 /opt/.manus/.host_id；supervisord 死亡则重启；dbus 死亡则重启；runtime 健康检查失败时：查更新锁 → 端口释放（含 lsof 强杀）→ supervisorctl stop/start 自愈。iptables 强制切到 legacy 模式（为 Docker 兼容预留）。

浏览器自动化栈

这是沙箱最精巧的部分：一套「真 GUI 浏览器 + 多端控制」的完整链路，让代理既能用 CDP 编程控制，也能模拟真人键鼠，还能让用户实时观看。

渲染层 — Xorg :0（1280×1029@24bit）

无窗口管理器（openbox 已禁用），Chromium 全屏独占。SwiftShader 软渲 WebGL，无需 GPU。

浏览器 — Chromium 151

安全与稳定性机制

🛡 拓扑环境冻结

startup.sh 在加载用户密钥前后做快照/恢复（capture_supervisor_runtime_env → restore），平台关键变量免遭 .user_env 覆盖；缺省键导出为空实现 fail-closed。

💉 凭据透明注入

manus-token-local-proxy（root、按需启动）：iptables 透明代理 + 请求级 token 替换，让沙箱内进程用占位凭据即可访问需鉴权服务，真实 token 不落用户空间。

📉 earlyoom 双层防护

root 实例（-m 10,5）+ 独立用户(61876)实例（-r 3600 每小时报告）；豁免正则保护 supervisord/runtime/Xorg/VNC/statesync/manus-* 等关键进程不被 OOM 误杀。

🔁 多级自愈

supervisord autorestart → startup.sh 每 10s 健康巡检（8330/8340）→ 端口强释 + stop/start 重启链 → 更新锁感知（升级中不误重启）→ SIGKILL 竞态不变量（commit 9821822a8 注释固化）。

🔐 终端隔离

ttyd 用 umask 077 的 unix socket + X-Manus-Terminal-User 请求头标识用户；bash 会话以 --noprofile --norc -i 启动确保环境纯净后再 source .env。

👁 进程事件审计

sandbox-process-observer 订阅 supervisor PROCESS_STATE 事件，进程启停全部落盘 ~/.local/state/manus/process-lifecycle 并上报 OTel。

🧹 冷缓存回收

envd 每 10s 回收冷页缓存（保留 1024MiB），长会话内存压力可控。

⏱ 时钟纪律

chronyd 平滑校时；仅在偏移>0.5s 时 makestep，避免 DNS 缓存雪崩、CPU 突刺与网络抖动（脚本内附 systemd-resolved 源码链接佐证）。
