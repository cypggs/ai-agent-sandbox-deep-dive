浏览器自动化四路线
深度对比：AppleScript · CDP · ego-lite · opencli

01

一句话看懂：四条路线的本质

同样是「读一个已登录网页」，四个方案走的链路完全不同——这决定了它们的能力上限与代价。

AppleScript

借道操作系统，遥控现成的浏览器。macOS 系统自带，零安装；Chrome 在 AppleScript 字典里暴露了 execute javascript。应急瑞士军刀，但链路脆弱、macOS 专属。

裸 CDP

以调试器身份接管浏览器内核。Chromium 原生调试协议，Playwright/Selenium 都构建于其上。能力天花板最高、跨平台；但要重启浏览器开调试端口，登录态默认带不过来。

ego-lite

浏览器本身就是为 Agent 造的。Chromium 深度定制 fork，引擎级 Snapshot + Spaces 人机共驾 + 官方 JS SDK。唯一「产品级」方案；代价是绑定一个闭源内核浏览器。

opencli

把你正在用的 Chrome 变成 CLI。Chrome 扩展 + 本地 daemon + Node CLI，不重装浏览器、不开调试端口，直接复用当前登录态；170+ 站点预置适配器，把网站变成确定性命令。

关键区分：四条路线其实回答的是三个不同问题——AppleScript 回答「如何不装任何东西就碰一下浏览器」；CDP 回答「如何获得浏览器的全部能力」；ego-lite 和 opencli 回答的是同一个问题「如何让 AI Agent 高频、低 token、可靠地操作真实登录态网页」——只是一个选择重造浏览器，一个选择给现成浏览器架桥。
02

架构全景：四张链路图

链路越短越可靠，链路越短也往往越不通用。注意每条链路里「登录态」在哪一环被继承。

① AppleScript —— 系统事件总线

你的脚本 → osascript → macOS Apple Events → Google Chrome.app（你日常那个）
                                              └─ execute javascript → 页面 JS → 返回字符串
前提：Chrome 菜单手动开启「允许 Apple 事件中的 JavaScript」+ 系统自动化授权

② 裸 CDP —— 内核调试协议

你的脚本 → HTTP/WebSocket（localhost:9222）→ Chromium 内核
                                              └─ Runtime.evaluate / Page / Network / Input ...（数百个命令）
前提：--remote-debugging-port 重启浏览器；Chrome 136+ 需独立 --user-data-dir，日常登录态默认不带

③ ego-lite —— 定制浏览器 + 原生绑定 + SDK

Agent（pi / Claude Code / Codex，读 SKILL.md 后写 JS）
   ▼
ego-browser CLI（原生二进制，随 App 装到 ~/.local/bin，~2MB）
   ▼ 启动 Node.js 进程，注入 SDK bundle（dist/out/index.js）
SDK 层（开源 TypeScript：taskSpace() / page.snapshot() / page.click() / page.evaluate()）
   ▼
globalThis.ego 原生绑定（浏览器进程内 NodeClient，闭源；含 ego.sendCDPMessage()）
   ▼
ego lite 浏览器 = Chromium 深度定制 fork（引擎级 Snapshot / Spaces 隔离 / Agent 光标）

注意：ego 底层也走 CDP（源码可见 cdp-eval.ts、ensureSession()），但额外叠加了浏览器进程内的原生通道，这是普通 Chrome 物理上给不了的。

④ opencli —— 浏览器扩展桥（不改浏览器本体）

Agent / 人 → opencli CLI（Node.js，npm 全局安装）
   ▼ WebSocket（localhost:19825）
micro-daemon（首个命令时自启动，常驻）
   ▼ Chrome Extension APIs
Browser Bridge 扩展（Chrome 商店安装）→ 在你日常的 Chrome 页面上下文里执行 JS
登录态：就是你 Chrome 里的登录态，零迁移、零调试端口
架构哲学差异：ego-lite 把复杂收进浏览器（你换浏览器，它给你最好的一致性）；opencli 把复杂收进扩展+daemon（你保留 Chrome，它给你最低的迁移成本）。两者都对外暴露了「Skill 文件 → Agent 读取 → 生成调用」的接入方式，但 ego 让 Agent 写代码（一次执行多步），opencli 让 Agent 调命令（JSON 契约逐条执行）——这直接对应两家在 README 里互相阴阳的「Code-based, not CLI-based」之争。
03

源码拆解：ego-lite 的三层结构

仓库 citrolabs/ego-lite（MIT），但注意：开源的是 SDK、Skill 和文档，浏览器内核本身闭源。

🔬 仓库里能看到什么 Fact

  • SDK（package/ego-browser/src，TypeScript）：driver 层（点击/键盘/导航/等待/下载）、ref 注册表、快照结果处理、任务空间生命周期。测试覆盖扎实——scripts/real-browser-e2e/cases/ 下有 30+ 个真实浏览器 e2e 用例（OOPIF、Shadow DOM、弹窗、下载、媒体播放都单独成案）
  • 原生绑定契约（docs/native-bindings-api.md）：浏览器侧 NodeClient 注入 globalThis.ego，方法返回 Promise，结果经 Chromium base::Value 转换；带完整错误码体系（EGO_TASK_SPACE_USER_IN_CONTROL、EGO_CDP_CHANNEL_UNAVAILABLE 等 15 个）
  • Skill 两层设计（docs/ego-browser-skill-command.md）：入口 Skill 只说「运行 ego-browser skill」，真正的使用指南随 SDK 版本化打包在 App 内打印——保证 Agent 读到的指南永远匹配已装浏览器版本
  • learnings 目录：github/google/x-com 等站点的预置「站点经验」（可复用工具脚本），对应 README 里「用得越多越快」的经验积累路线

🧠 它真正稀缺的三件事 Analysis

  • 引擎级 Snapshot：README 直言 "customization inside the browser engine"。输出带 @ref 引用的无障碍树文本，供纯文本模型「看见」页面，并声称可靠处理深层嵌套 iframe——这正是普通 CDP 拼 a11y 树最容易崩的地方
  • Spaces 人机共驾：同一浏览器内的隔离工作区，Agent 不占用户标签页；handOff()/takeOverTaskSpace() 是协议级能力，用户接管时浏览器会拒绝 Agent 的变更类调用（绑定文档里明确列了被阻断的 API 清单）
  • 可见的 Agent 光标：操作时有可视化光标与动作标签（click 等 API 收 label 参数），人机协作的「信任界面」
代价：内核闭源意味着快照质量、指纹特征、隐私边界都只能信官方；目前仅 macOS/Windows，Linux 在 roadmap；你的日常浏览器需要从 Chrome 迁移到 ego lite（官方提供 Chrome 数据一键迁移：Cookie/扩展/书签）。
04

源码拆解：opencli 的桥接设计

仓库 jackwener/opencli（Apache-2.0，★30,487，TypeScript/JavaScript）。本机实测已安装 v1.8.7（brew），pi 内装有 opencli-adapter-author skill。

🔬 仓库里能看到什么 Fact

  • 三段式桥接：CLI（Node.js ≥20.18.1）→ WebSocket localhost:19825 → 自启动 micro-daemon → Chrome 商店分发的 Browser Bridge 扩展 → 在页面上下文执行 JS。不重启浏览器、不开调试端口、不换浏览器，登录态零成本继承
  • 170+ 站点适配器（docs/adapters/browser/ 下 170 个文档）：小红书/B站/知乎/X/Reddit/LinkedIn/亚马逊/Midjourney……把「读热榜」「发评论」「抓通知」变成 opencli bilibili hot --limit 5 这样的确定性命令
  • Agent 契约：所有命令默认输出 JSON {ok, data} / {ok:false, error:{code,message,hint}}，非零退出码，日志走 stderr——为机器消费设计，不是给人看的 CLI 改出来的
  • 四个官方 Skill：opencli-browser（通用页面操作）、opencli-adapter-author（端到端写新适配器：侦察→端点发现→鉴权选型→字段解码→验证）、opencli-autofix（修坏掉的适配器）、opencli-usage（命令速查）
  • 会话与租约管理：--session 命名会话隔离并行任务；owned tab 10 分钟空闲超时、bind 附着用户手开的标签页、site slots 池化热标签页；chrome call 直接调原生 Chrome API 管理标签组
  • 也留了 CDP 口：OPENCLI_CDP_ENDPOINT 可接远端浏览器（CI/服务器场景），远程编排官方推荐 SSH 反向隧道

🧠 它真正稀缺的三件事 Analysis

  • 适配器生态 = 复利的确定性：通用浏览器 Agent 每次都在「现场理解页面」；opencli 把理解结果沉淀成代码（适配器），同站第二次之后是零 LLM 成本的确定性执行——和 ego 的 learnings 思路相似，但 opencli 的沉淀物是社区共享的 Apache-2.0 代码
  • 「网站 → CLI」的双向价值：同一条命令人能用、脚本能用、Agent 也能用。它不只是 Agent 工具，本身也是生产力 CLI
  • 适配器维修闭环：autofix skill 专门应对「网站改版把适配器打挂」这一结构性痛点，把维护成本也 Agent 化了
代价：CLI 逐命令调用，复杂多步任务的编排 token 开销高于「写一段 JS 一把跑完」的 ego 模式（ego README 的基准测试正是拿 CLI 类工具当靶子，自称快 47–63%）；原生输入（真实点击/键盘）要求页面 visibilityState === 'visible'，后台标签页会被拒；daemon 常驻本地端口意味着本机任何进程理论上都能借桥操作浏览器。

实测：同一任务，三种跑法

任务：读取内网发布系统（需登录）一个 110 行的版本明细表，按 5 个状态列统计就绪比例。AppleScript 与 ego-browser 为馆长亲测；opencli 本机已装（v1.8.7）但本次未跑同任务，标注清楚。

07

安全面：各自的攻击面

四个方案都等于「把已登录浏览器的读（甚至写）能力开放给本机程序」，但开放方式不同，暴露面也不同。

⚠️ 攻击面对比 Analysis

  • AppleScript：任何能执行 osascript 的进程都能读你全部已登录页面。开关在 Chrome 菜单里，很多用户开过就忘了
  • 裸 CDP：localhost:9222 是无认证后门，本机任意进程可用；若绑定 0.0.0.0 则等价于把浏览器开给整个内网。历史上被恶意软件利用过多次
  • ego-lite：控制面在浏览器进程内（不监听网络端口），暴露面最小；用户接管期间协议级拒绝 Agent 变更操作。但内核闭源，数据收集与指纹只能信官方「数据留在本地」的声明
  • opencli：daemon 监听 localhost:19825（README 未描述认证机制），本机任意进程理论上可借桥操作浏览器；扩展需「读取所有网站数据」权限。好在全开源，可审计

🛡️ 加固建议

  • 敏感操作后关闭 Chrome 的「允许 Apple 事件中的 JavaScript」
  • CDP 端口只绑 127.0.0.1，用完即关；绝不在生产服务器无保护暴露
  • 定期 opencli daemon stop；多 profile 场景用 profile use 收敛默认身份
  • 把「会写」的操作（发消息、下单、删除）与「只读」巡检分开授权；ego 的 Spaces 接管机制天然适合做这个边界
  • 内部系统巡检类任务，优先只读命令（state/extract/eval），避免 publish/follow 类写操作适配器进入自动化循环
08

选型建议与决策树

需要操作浏览器？
├─ 一次性救急，macOS 本机，读完就完 ──────────► AppleScript（零依赖，10 秒上手）
├─ 写可复用工具 / 需要抓包·性能·拦截 / CI 无头 ─► 裸 CDP（配 Playwright，业界标准）
└─ AI Agent 高频操作真实登录态网页？
   ├─ 任务杂而散、页面千变万化、看重人机共驾 ──► ego-lite
   │   （引擎 Snapshot 省 token，Spaces 不抢浏览器，写代码一把过）
   └─ 站点相对固定、要确定性、要社区可复用 ────► opencli
       （170+ 适配器开箱即用，新站点沉淀为自己的适配器，Apache-2.0 可审计）
馆长判断 Analysis：ego-lite 与 opencli 不是替代关系，而是互补的两个频段——ego 强在「长尾陌生页面的第一次理解」（Snapshot 质量 + 代码化编排），opencli 强在「已知站点的第 N 次确定性执行」（适配器生态 + JSON 契约）。成熟的 Agent 工作台会两者都装：陌生页面用 ego 趟路，趟熟了的流程写成 opencli 适配器固化。AppleScript 留在急救箱，裸 CDP 留给造工具的人。
